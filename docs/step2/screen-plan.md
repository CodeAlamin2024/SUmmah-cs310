# SUmmah — Step 2 Screen Plan

CS310 Mobile Application Development · Group 35 · Step 2.1 planning

## Purpose
Document the proposed mobile screens for SUmmah before preparing the Step 2.1 wireframe PDF. These are planning notes, not approved wireframes.

## Proposed screens

| Screen | Purpose | Main elements and interactions |
| --- | --- | --- |
| Home | Give students an immediate view of upcoming prayers | Current date/time, next prayer and iqamah countdown, today’s timetable preview, Jumu'ah and announcements shortcuts |
| Timetable | Show campus-specific daily prayer information | Five prayer rows with adhan and iqamah times, selected date, next-prayer highlight |
| Announcements | Show masjid updates | Announcement cards with title, date, summary and detail; removable cards for a demo list in Step 2.2 |
| Jumu'ah | Show Friday prayer information | Jumu'ah schedule, location/instructions and relevant notices |
| Admin Login | Entry to authorized content management | Email and password fields, login button, sign-up link; UI-only in Step 2.2 |
| Sign Up | Demonstrate account registration UI | Name, email, password, confirmation/validation; UI-only in Step 2.2 |
| Admin Dashboard | Navigate to editable content | Timetable and announcement management actions, list of records |
| Edit Form | Demonstrate creating/updating information | At least two fields, inline validation and confirmation dialog on valid submission |

## Step 2.1 deliverable
- Produce a wireframe for each screen required by the approved Step 1 scope, including login, sign-up and relevant forms.
- Label navigation controls and show transitions between screens.
- Add a short explanation for each screen.
- Export one group PDF named `CS310_Group35_Step2.1.pdf` and submit by **8 November 2026, 23:59**.
- Obtain TA feedback before UI implementation.

## Step 2.2 UI checklist
- Working navigation between approved screens; placeholder data is acceptable.
- Reusable widgets and shared styles; responsive portrait layouts without overflow.
- Local and network images, a custom font, and model-object Cards with a working remove action.
- A form with at least two fields, inline errors and a confirmation dialog.
- Login/sign-up UI only; Firebase integration is planned for Step 3.
- Runnable Flutter project, public repository, README run instructions and Flutter version.
- PDF with labeled screenshots, repository URL, deadline commit ID and member contributions.
